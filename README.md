# Notifilter

Android-приложение, которое автоматически убирает уведомления, совпавшие с
пользовательскими регулярными выражениями. Полезные уведомления того же
приложения остаются на месте.

## Что уже есть

- правила для конкретного package name или для всех приложений;
- поиск по заголовку, основному тексту либо всем доступным текстовым полям;
- действия «Скрыть» и «Разрешить» (разрешающее исключение имеет приоритет);
- проверка выражения и тестовая строка до сохранения;
- отдельные выключатели для каждого правила и всей фильтрации;
- журнал уведомлений, для которых сработало правило, с поиском, просмотром и очисткой;
- безопасный режим: звонки, будильники, media/ongoing, foreground-service,
  group-summary, non-clearable и системные уведомления не удаляются;
- локальная Room-БД без разрешения `INTERNET` и аналитики.

## Как это работает

Android связывает `FilteringNotificationListenerService` после того, как
пользователь вручную включит специальный доступ к уведомлениям. Сервис извлекает
стандартные поля из `Notification.extras`, проверяет заранее скомпилированные
выражения RE2/J и вызывает `cancelNotification(key)` при совпадении. До первой
загрузки правил после запуска сервиса уведомления пропускаются (fail-open).

Это принципиальное ограничение платформы: уведомление уже опубликовано к моменту
callback. Поэтому карточка, heads-up, звук или вибрация иногда могут успеть
появиться. Удалённое чужое уведомление нельзя надёжно восстановить. Текст внутри
нестандартного `RemoteViews` также может быть недоступен.

## Сборка

Локальная сборка в этом репозитории не требуется: debug и release проверяются в
изолированном GitHub Actions runner файлом `.github/workflows/android.yml`.
Workflow запускает JVM/Robolectric-тесты, Android lint и обе сборки, затем
публикует debug APK как artifact `notifilter-debug`.

Ручной запуск и получение результата выполняются только через `gh`:

```bash
gh workflow run android.yml --repo nvprotas/notifilter
gh run list --repo nvprotas/notifilter --workflow android.yml
gh run download RUN_ID --repo nvprotas/notifilter --name notifilter-debug
```

После установки APK:

1. Нажмите «Разрешить доступ» и включите Notifilter в системном списке.
2. Создайте правило, выберите приложение и проверьте regex на тестовой строке.
3. Включите главный переключатель фильтрации.

Пример выражения для рекламных слов:

```regex
скидк[аи]|промокод|только сегодня|успейте купить
```

Совпадение ищется внутри текста. Для полного совпадения используйте `^…$`.
Используется безопасный линейный синтаксис RE2: обратные ссылки и lookaround
(`(?=...)`, `(?!...)`, `(?<=...)`) намеренно не поддерживаются.

## Журнал

Журнал выключен по умолчанию и включается пользователем отдельно. После запроса
на скрытие в него локально записываются приложение, время, видимые заголовок и
основной текст, сработавшее правило и статус: запрос на скрытие либо
подтверждение Android. Поиск работает также по отображаемому имени приложения.
Хранится не более 1000 записей; записи старше 30 дней удаляются при следующем
запуске приложения/сервиса или добавлении записи. Журнал можно выключить,
очистить целиком или удалить отдельную запись.

Журнал показывает то, что успел получить Notification Listener. Это не
восстанавливает исходную карточку в системной шторке и не гарантирует извлечение
текста из нестандартного `RemoteViews`.

## Приватность и безопасность

Notifilter получает доступ к потенциально чувствительным уведомлениям только для
локальной проверки правил. Если журнал включён, видимое содержимое уведомлений,
для которых отправлен запрос на скрытие, сохраняется в закрытой базе приложения
с указанной выше политикой очистки.
Приложение не имеет сетевого разрешения и не использует рекламу, аналитику или
crash-reporting. Backup и перенос данных запрошены как отключённые, а база и
настройки дополнительно исключены из правил Android backup/device transfer.

Подробная политика: [docs/PRIVACY.md](docs/PRIVACY.md).

## Структура

- `domain/RuleMatcher.kt` — чистый и тестируемый движок правил;
- `notification/` — извлечение текста и `NotificationListenerService`;
- `data/` — Room и локальные настройки;
- `ui/` — Compose-интерфейс управления правилами и доступом.
